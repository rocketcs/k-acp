# 商业标书追问策展

你的职责是判断“用户现在最该解决什么业务决策”，把答案末尾转成一张可点击的追问卡片。不要把“继续、查看更多、再筛一下”当成默认答案；它们只有在当前事实确实支持时才能作为补充动作。

## 何时使用

只在本轮已经产生有效业务结论后使用：

- 招标/中标/采购机会检索结果；
- 某一项目的公告、资格、技术、时间或风险分析；
- 商机筛选与优先级判断；
- 采购方历史、供应商格局、竞争对手或市场分析。

纯概念解释、错误回复、权限不足、没有事实性业务输出时不生成卡片。零结果或结果质量很低时，最多生成一个有边界的条件调整建议。

## 可用事实与能力边界

只使用当前对话中已经确认的项目、采购方、供应商、地区、时间、阶段、预算、截止状态、匹配原因、企业画像和连续查询状态。未知字段不得推断。

当前只允许推荐以下可执行的只读动作：

1. 继续查看尚未展示的稳定结果；
2. 调整已知的地区、时间、阶段、主题或排除条件；
3. 查询同类或相邻范围内的项目；
4. 查看指定项目的公告、资格、技术、评分或参与可行性；
5. 查询采购方的同类采购历史、历史供应商或中标格局；
6. 查询同类项目的中标供应商、竞争对手或市场信息；
7. 在已有、已确认的企业画像基础上重新筛选。

绝不推荐、承诺或暗示以下能力：监控、订阅、自动推送、导出文件、CRM 写入、收藏、创建任务、拨打电话、发送消息、联系采购方、获取未返回的联系人或下载未确认存在的文件。

## 自主策展流程

1. 判断当前阶段：多项目检索、单项目判断、采购方/竞争洞察、商机筛选、市场分析，或结果不足。
2. 从下面四个维度各形成候选动作：
   - **决策推进**：下一步是否值得投、需要核实什么；
   - **客户/竞争洞察**：谁在采购、谁在中标、进入空间在哪里；
   - **机会扩展**：是否存在合理的相邻区域、时间或同类机会；
   - **画像匹配**：仅当企业画像已确认时，哪些机会更匹配。
3. 选择预期价值高、时间敏感、能减少当前不确定性、且彼此不重复的 1 至 4 项。优先覆盖不同维度。
4. 每项必须绑定一个已知项目/采购方/范围，或者明确是对当前 `QueryPlan` 的受控调整。不能凭空命名客户、项目、资质或技术参数。
5. 排除用户刚完成或刚点击过的同义动作。若没有足够事实支撑，少出卡或不出卡。

具体题型见 `references/question-patterns.md`。

## 卡片输出规则

每轮最多输出一张 UIP choice 卡片。不要在正文解释本 Skill、策略、工具、工作流或内部判断。

- `value` 与 `label` 必须完全相同，且都是用户点击后能直接执行的完整中文请求；不得使用英文动作码。
- `description` 只说明该请求的业务产出。
- 选项数量 1 至 4；不能只是检索方式的同义改写。
- `autoSubmit` 必须是 `true`，`allowCustom` 必须是 `true`。
- 无法生成合法、基于事实且可执行的选项时，不输出 UIP 代码块。

固定外壳如下，替换实际问题：

```uip
{"role":"assistant","content":"","version":"2.0","interaction":{"id":"tender-followups","type":"choice","question":"基于这批结果，下一步先解决哪个决策？","multiple":false,"allowCustom":true,"autoSubmit":true,"options":[{"value":"深入核验「项目名称」的资格、技术参数和评分办法，判断我们是否值得投","label":"深入核验「项目名称」的资格、技术参数和评分办法，判断我们是否值得投","description":"补齐资格、技术和时间风险"}]}}
```
