# 医保问数助手客户讲解流程图设计

## 目标

将现有技术流程图改为客户可直接理解的产品使用流程，供销售在客户现场讲解。客户是流程中的最终使用者；销售人员只作讲解，不作为流程节点。

## 受众与成功标准

- 受众：医保问数助手的潜在客户与最终使用者。
- 时长：销售可在约 1 分钟内讲清流程与价值。
- 可理解性：不出现 SQL、MDL、Neo4j、工具协议、内部字段名或英文技术缩写。
- 可信性：清楚说明答案来自已接入、受权限控制的医保数据；信息不足时助手先确认，不会猜测。

## 信息架构

采用由左至右的 5 步主流程，并保留一个最小的确认回路：

1. **提出问题**：客户用日常语言提问，也可以基于推荐问题继续追问。
2. **理解需求**：助手识别客户关注的医保项目、地区、时间与查询目标。
3. **必要时确认**：当问题缺少关键条件或存在多种理解时，助手以选择或补填的方式请客户确认，然后回到理解需求。
4. **查询权威数据**：助手在权限范围内查询已接入的医保目录与业务数据，并校验查询条件。
5. **获得可信答案**：客户看到清晰结论、完整明细、适用口径和可追溯来源；需要时可继续追问。

## 版式与文案

- 标题：`医保问数助手：从提问到可信答案`。
- 每一步只保留一条动作标题与 1–2 行客户语言说明。
- 以蓝、青、橙、紫、绿五种低饱和色区分阶段；确认分支用橙色，清晰体现“先确认，再查询”。
- 第 4 步以“权威数据、权限控制、条件校验”解释可信查询，不展示系统组件名称。
- 第 5 步以“答案、明细、口径、来源、继续追问”展示客户可见结果。
- 底部用一句价值总结：`说业务语言，查可信数据，给清晰答案。`

## 非目标

- 不展示内部服务、数据库、模型、图谱、协议或调用顺序。
- 不改变产品行为、前端、后端或数据查询规则。
- 不在图中承诺尚未完成的能力。

## 验证

- 以 XML 校验确保 draw.io 文件可被 diagrams.net 打开。
- 复查全部图中文字：无内部技术缩写与实现细节；五步流程与确认回路均可独立读懂。
