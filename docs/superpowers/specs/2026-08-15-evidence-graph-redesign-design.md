# 医保目录问数智能体 · 右侧证据图谱语义展示优化设计

> 状态：待用户审阅（2026-08-16）
>
> 范围：优化右侧“语义依据”中知识图谱相关的语义文案，并微调医保目录语义 skill 与该智能体的本地执行 Prompt，使查询稳定带回可读的关系与来源证据。
> 不在本次范围：页面布局、主题色、MDL 结构页、图谱布局/交互、Neo4j、MCP 证据契约。

## 1. 背景

当前右侧图谱已能呈现查询命中的业务实体、业务关系和来源追溯，但其语义表达仍偏技术化：

- 节点和边存在 `kind`、关系码、内部记录标识等技术语义，业务人员不能直接理解。
- 图谱边的“业务关联”“来源追溯”等泛化标签没有回答“谁和谁是什么关系”。
- 来源数据可能以物理表名、哈希或内部 ID 呈现，无法形成可读的审计依据。
- 选中节点摘要按边集合拼接，容易出现“关联到/来自”之类缺乏业务含义的句子。

本设计将知识图谱定义为**本次查询的可读证据关系**：它解释结论与证据，不能被称为或表现为全库 Neo4j 知识图谱浏览器。

## 2. 目标与边界

### 2.1 目标

普通业务查询人员无需理解 MDL、Neo4j、内部表或数据导入过程，也能从右侧图谱读懂：

1. 查询命中了什么业务实体；
2. 它与哪些业务实体存在什么关系；
3. 这些信息由什么来源记录佐证；
4. 本次查询为何得出该结论（按需查看）。

上游查询必须选择支撑上述说明的已发布字段；不能只返回回答文本所需的单个字段。

### 2.2 严格边界

- 保持现有三栏页面、右侧面板、Tab、图谱画布、工具栏、筛选和交互位置不变。
- 保持现有主题色、字体、背景和视觉语言不变；只复用现有绿色、青蓝、蓝灰和橙色语义色。
- 不调整 MDL 结构 Tab，不变更其数据与文案。
- 不改变节点、边、`semantic_context` 或来源记录的返回结构；不修改 Neo4j、MCP、Wren MDL 或后端。
- 医保目录语义 skill 和本地智能体执行 Prompt 只约束字段选择、模板执行和证据完整性；它们不生成面向用户的自由图谱文案。
- 不新增、猜测或补全业务事实；所有语句必须由当前 evidence envelope 的节点、边和来源信息推导。

## 3. 核心设计决策

| 决策点 | 决策 | 原因 |
|---|---|---|
| 图谱定位 | “本次查询的证据关系” | 精确反映当前仅展示查询子图的事实，避免误称全库知识图谱 |
| 语义策略 | 节点业务化、关系动词化、来源可定位、技术字段隐藏 | 使业务人员一眼看懂关系与依据 |
| 摘要策略 | 主体优先的自然语言摘要，最多 3 条 | 先交付结论，避免图谱成为阅读负担 |
| 词典策略 | 原始关系不变，新增纯前端展示词典 | 不影响数据模型与现有查询能力 |
| 上游证据 | skill 与执行 Prompt 要求查询带回主体、关系目标和来源字段 | 防止前端只有孤立字段，无法生成真实证据语句 |
| 未知数据 | 可读保底或隐藏 | 不将关系码、哈希、物理表名、内部记录 ID 暴露给业务人员 |

## 4. 展示语义规范

### 4.1 节点文案

节点由“类型标题 + 可读业务值”构成。类型标题复用已有业务分类，值必须是对用户有意义的业务信息。

| 节点类别 | 展示格式 | 示例 | 禁止展示 |
|---|---|---|---|
| 查询命中 | `查询命中：{名称}` | `查询命中：覆膜气管支架` | product ID |
| 注册备案 | `注册备案：{号码}` | `注册备案：国械注准20173134669` | registration ID |
| 生产企业 | `生产企业：{名称}` | `生产企业：淮安市西格玛医用实业有限公司` | organization ID |
| 分类/概念 | `{类型}：{名称或编码}` | `目录分类：气管支架` | namespace 内部值 |
| 原始记录 | `原始目录记录：{可定位来源}` | `原始目录记录：耗材谈判记录 · 第 6 表 · 第 2 行` | record ID、行哈希 |
| 来源文件 | `来源：{文件名}` | `来源：耗材谈判记录` | 物理表名 |
| 导入批次 | 默认不向业务用户显示 | — | batch ID、导入哈希 |

缺少可读值的节点不作为业务节点呈现。来源链仅在能够提供至少一个可读层级（文件、工作表、行号）时展示。

### 4.2 关系词典

原始 `edge.kind`、`edge.label` 和 Neo4j 关系保持不变。前端展示层依据节点类型和原始关系映射出短标签与完整句式。

| 语义类别 | 原始关系示例 | 图谱边短标签 | 摘要句式 |
|---|---|---|---|
| 业务对应 | `对应` | `对应注册备案` | `{主体}对应{对象类型}：{对象}` |
| 生产 | `生产` | `生产企业` | `{主体}由{对象}生产` |
| 分类归属 | `归类`、`CLASSIFIED_AS` | `归属分类` | `{主体}归属{对象}` |
| 映射 | `映射`、`ASSERTED_MAPS_TO_CONCEPT` | `映射至` | `{主体}映射至{对象}` |
| 价格/支付 | `限价支付` | `医保支付` | `{主体}适用{对象}` |
| 原始证据 | `证据支持`、`EVIDENCE_FOR` | `原始记录佐证` | `该信息由{对象}佐证` |
| 文件溯源 | `包含`、`CONTAINS_RECORD` | `收录于来源工作簿` | `记录收录于{对象}` |
| 未识别 | 其他关系 | `相关` | `{主体}与{对象}相关` |

边上只显示短标签；完整句只在问题摘要和已选节点摘要中显示，以避免边文字遮挡图谱。

### 4.3 关系摘要

在现有“当前问题”图谱区域的问题摘要中增加一行只读“关系摘要”，不移动或新增面板。

拼装规则：

1. 以本轮查询命中的业务实体为主体；没有该节点时不生成业务关系摘要。
2. 按“直接业务关系 → 原始记录佐证 → 文件/工作表/行号来源 → 其他关系”的顺序排序。
3. 最多显示三句，超出的信息以“另有 N 条关联”收束。
4. 相同主体、关系和对象只显示一次。
5. 缺少名称的节点和未定位的来源不参与摘要。

示例：

> 关系摘要：覆膜气管支架对应注册备案号：国械注准20173134669。该信息由《耗材谈判记录》第 6 表第 2 行佐证。

### 4.4 已选节点摘要

保留现有已选节点摘要区域和交互，仅更新文案：

- 标题展示节点业务类型和业务值。
- 关联条目使用完整关系句，而不是“关联到/来自”。
- 来源条目展示文件名、工作表、行号；有缺失时只展示已有层级。
- 单个节点最多显示四条完整关系，其他关系保持“另有 N 条关联”。

示例：

> 注册备案：国械注准20173134669
>
> 覆膜气管支架对应该注册备案。
> 该信息由《耗材谈判记录》第 6 表第 2 行佐证。

## 5. 上游证据选择

### 5.1 医保目录语义 skill

在现有“字段落点”和“模板优先”规则之后，新增证据字段规则。语义解析的结果应包含 `evidence_columns`，其值必须来自已发布字段白名单，且是 `published_columns` 的子集。

| 查询意图 | 必须选择的业务字段 | 必须选择的来源字段 |
|---|---|---|
| 注册备案号/批准文号 | `catalog_name`、`registration_no` | `source_record_id` |
| 生产/耗材企业 | `catalog_name`、`manufacturer` 或 `consumable_enterprise` | `source_record_id` |
| 耗材分类 | `catalog_name`、`category_level_1`、`category_level_2`、`category_level_3` | `source_record_id` |
| 支付类别/限额/价格 | `catalog_name`、被问字段；价格必须附带 `price_semantics` | `source_record_id` |
| 有效期或政策 | `catalog_name`、`valid_from`、`valid_to` 或 `policy_no` | `source_record_id` |

`evidence_columns` 不改变 MCP 契约；它仅向智能体声明最终模板或 SQL 投影必须包含的字段。无法获取来源字段时，解析结果应保留业务字段并标记“来源不可用”，不能伪造来源。

### 5.2 智能体执行 Prompt

本地 `default-graphify-data-query` 智能体的执行 Prompt 增加以下硬规则：

1. 涉及具体医保目录事实时，必须执行经 `query_preflight` 允许的 `query`（不使用任何预定义查询模板），不能仅依据 `semantic_context` 回答。
2. 最终查询除回答字段外，必须投影 skill 给出的 `evidence_columns`。
3. `catalog_name` 是业务主体；如结果缺少它，智能体不得声称返回记录具有可读关系。
4. `source_record_id` 仅用于 MCP 生成证据节点或来源追溯，不在回答文本和业务图谱文案中直接展示。
5. 智能体不得编造节点、边、来源文件、工作表或行号；未返回证据时应明确说明“本次结果未提供可追溯来源”。

Prompt 只控制工具调用和投影字段；面向用户的节点标题、关系短标签和摘要句式仍由前端固定词典生成。

## 6. 展示位置与数据流

```text
用户问题
  → 医保目录语义 skill（字段落点 + evidence_columns）
  → 智能体执行 Prompt（工具调用 + 最终字段投影）
  → 当前 evidence envelope（nodes / edges / 来源信息）
  → 关系展示适配层
      ├─ 节点可读名称
      ├─ 边短标签
      ├─ 关系完整句
      └─ 关系摘要与来源定位
  → 既有图谱画布、问题摘要、已选节点摘要
```

展示适配层只消费已有数据。它不发起 Neo4j 查询、不请求 MDL 详情、不改变图谱元素数量或布局，也不写回任何数据。

## 7. 降级与安全规则

| 场景 | 展示行为 |
|---|---|
| 无业务关系、仅有来源 | `本次结果可追溯至：{来源}` |
| 无来源、存在业务关系 | 仅展示业务关系，不宣称已佐证 |
| 来源缺少工作表或行号 | 只显示文件名或已有层级，不虚构位置 |
| 未识别关系 | 显示“相关”；若对象也不可读，则隐藏该关系 |
| 存在内部 ID、哈希、物理表名 | 不作为业务用户文案输出 |
| 没有可读节点或边 | 保留既有空态，不生成摘要 |
| skill 未能提供来源字段 | 执行查询但不承诺来源追溯；前端仅展示已返回的业务关系 |

## 8. 验收标准

| 需求 | 通过条件 |
|---|---|
| 节点业务化 | 图谱与节点摘要不显示 `kind`、关系码、哈希、物理表名、内部记录 ID |
| 关系动词化 | 业务边和溯源边均有可读短标签；摘要中均为完整关系句 |
| 来源可定位 | 有文件、工作表、行号时按该顺序展示；缺失信息不编造 |
| 一致性 | 同一关系在边、关系摘要、已选节点摘要中语义一致 |
| 数据忠实 | 所有文案可由原始 nodes/edges/来源字段反向验证；不新增事实 |
| 视觉无回归 | 页面布局、主题色、MDL Tab、图谱交互和布局保持现状 |
| 上游完整性 | 注册备案、企业、分类三类问题的最终投影均包含 `catalog_name`、关系字段和 `source_record_id` |
| 工具纪律 | 具体目录事实必须有 `query` 的 executed evidence（经 `query_preflight` 允许），不能由 `semantic_context` 直接作答 |

## 9. 典型验收样例

| 输入事实 | 预期文案 |
|---|---|
| `覆膜气管支架 --对应--> 国械注准20173134669` | `覆膜气管支架对应注册备案号：国械注准20173134669。` |
| `目录项 --证据支持--> 原始记录 --包含--> 耗材谈判记录 / 第 6 表 / 第 2 行` | `该信息由《耗材谈判记录》第 6 表第 2 行佐证。` |
| `目录项 --生产--> 某企业` | `覆膜气管支架由某企业生产。` |
| 未知关系，双方名称完整 | `{主体}与{对象}相关。` |
| 仅返回内部记录 ID | 不展示该节点或关系；不以 ID 代替业务名称 |
| 用户问“覆膜气管支架注册备案号” | skill 选择 `catalog_name`、`registration_no`、`source_record_id`；智能体执行最终查询；前端显示“覆膜气管支架对应注册备案号：…” |

## 10. 范围外

- 改动右侧面板或整页布局。
- 改动主题色、字体、节点形状、图谱布局或已有交互。
- 重做或下线 MDL 结构 Tab。
- 按节点数量切换为卡片、图谱或其他表现形态。
- 新增全库知识图谱浏览、数据治理页、权限或模型管理能力。
- 修改 Neo4j 数据模型、导入 Cypher、MCP 工具或 evidence envelope。
