# 商业标书智能体提示词与技能设计

## 背景

当前“商业标书智能体”已经具备 `tender-search`、当前日期查询和公共 `http_request` 能力，但绑定的系统提示词来自“政企部运营问数智能体”，内容围绕 Wren 和 SQL 查询，无法稳定完成招标商机搜索、筛选和跟进分析。

本设计为该智能体新增专用系统提示词和一个按需加载的商机分析技能。目标是接近竞品的商机分析效果，同时避免系统提示词过长或一次查询执行过多分析：默认快速搜索，用户提出进一步要求后再逐阶段深入。

## 目标

- 将智能体定位为面向销售和商务人员的商业标书商机助手。
- 支持“通用规则 + 企业画像”的混合匹配模式。
- 使用三阶段交互控制分析深度和工具调用成本。
- 将系统提示词保持为短路由层，避免重复装载招标接口和深度分析规则。
- 复用现有 `tender-search`，新增一个按需加载的 `tender-opportunity-analysis` 技能。
- 返回真实、可点击的项目外部链接。
- 不限制有效项目总条数；项目较多时使用折叠分组降低首屏长度。
- 对缺失字段、接口错误和超长结果采取明确且不编造的降级方式。

## 非目标

- 第一版不新增招标数据接口或 HTTP 工具。
- 不拆分多个系统提示词、子智能体或工作流。
- 不把商机筛选和单项目分析拆成多个独立技能。
- 第一版不实现 Excel 导出。
- 第一版不自动完成投标文件编制。
- 不在普通搜索请求中对每个项目执行详情查询或深度评分。

## 上下文与职责架构

K-ACP 为智能体绑定一个系统提示词模板。技能启动时只暴露名称和描述，完整 `SKILL.md` 在模型选择使用后才加载。因此采用以下三层结构：

1. **短系统提示词（常驻路由层）**：只定义角色、三阶段路由、真实性边界、折叠规则和连续追问规则，目标长度约 600 至 1000 个中文字。
2. **现有 `tender-search`（数据查询层）**：负责接口选择、查询参数、当前日期、HTTP 调用、详情获取和真实项目链接。系统提示词不得重复这些接口细节。
3. **新增 `tender-opportunity-analysis`（按需分析层）**：只在用户要求筛选、优先跟进或深入分析时加载，负责企业画像匹配、商机分级和单项目风险分析。

新增分析技能包含一个精简入口和两个按需参考文件：

- `SKILL.md`：触发条件、阶段路由、共享数据边界。
- `references/screening.md`：重点筛选、企业画像和三级商机规则。
- `references/project-analysis.md`：单项目资格、技术、时间、竞争风险和跟进动作。

不创建多个系统提示词，因为同一智能体无法按阶段动态绑定多个模板；不创建多个分析技能，因为筛选和单项目分析共享上下文，拆分过细会增加技能选择错误。

## 角色与行为原则

短系统提示词将智能体定义为“商业标书商机助手”，并指示它根据用户当前意图加载对应技能。智能体面向业务用户输出结论，不展示工具调用、接口参数、内部推理或评分过程。

基本原则：

- 先回答用户当前阶段的问题，不主动扩展成完整研究报告。
- 使用来源数据中的项目名称、链接、预算、日期和联系人，禁止猜测或补写。
- 缺少企业画像时使用通用规则；存在企业画像时自动切换为定制匹配。
- 沿用同一对话中的查询条件、项目编号和企业画像，支持“分析第 2 个项目”等连续追问。

## 三阶段交互

### 第一阶段：快速搜索

适用于“查一下最近的服务器采购项目”等搜索请求。

执行内容：

1. 识别关键词、地区、时间范围和截止状态。
2. 获取当前日期，必要时扩展同义词和相关采购方向。
3. 使用 `tender-search` 和 `http_request` 查询项目。
4. 剔除明确已截止和明显无关的记录。
5. 返回项目名称链接、采购人、地区、预算、截止时间及简短匹配标记。

本阶段只加载 `tender-search`，不加载 `tender-opportunity-analysis`，不逐项查询详情，不生成复杂分数，不主动分析资格、技术参数和竞争风险。

### 第二阶段：重点筛选

仅在用户提出“哪些值得跟进”“帮我筛选”等要求后执行。

执行内容：

1. 加载 `tender-opportunity-analysis` 的商机筛选规则，从当前候选项目中筛选重点商机。
2. 有企业画像时参考主营产品、资质、案例、重点区域和预算偏好；没有时使用通用行业与商业价值规则。
3. 将项目分为“优先跟进、重点关注、储备关注”。
4. 重点分析最有价值的 3 至 5 个项目，给出简短匹配理由和主要风险。

本阶段使用“高、中、低”或三级商机分类，不使用容易造成虚假精确感的复杂 100 分制。

### 第三阶段：单项目深入分析

仅在用户指定项目或明确要求深度分析后执行。

执行内容：

1. 加载 `tender-opportunity-analysis` 的单项目分析规则，并通过 `tender-search` 查询项目详情和原始公告。
2. 补充联系人、资格条件、技术参数和关键时间节点。
3. 分析品牌限制、地域限制、业绩要求、交付周期及其他参与风险。
4. 给出可执行的跟进动作。

## 数据流与工具策略

1. 短系统提示词先判断用户处于快速搜索、重点筛选还是单项目分析阶段。
2. 快速搜索只加载 `tender-search`，解析条件、获取当前日期并查询列表。
3. 重点筛选加载 `tender-opportunity-analysis` 的 `references/screening.md`，只对最有价值的候选项目补查详情。
4. 单项目分析加载 `references/project-analysis.md`，再通过 `tender-search` 获取指定项目详情。
5. `http_request` 只调用技能规定的接口，不得自行猜测接口路径。
6. 所有外部链接直接使用接口返回的 URL。

工具失败时保留已经获得的有效数据，并说明哪些字段尚未获取。不得把接口错误包装成成功结果。

## 企业画像匹配

企业画像可来自当前对话、智能体记忆或后续配置，包含：

- 主营产品和技术方向
- 可用资质与历史案例
- 重点服务区域
- 偏好的项目规模和采购类型
- 明确排除的业务方向

若画像存在，只使用用户已经提供或系统明确保存的事实。若画像不存在，不阻塞搜索，自动采用通用规则并以“通用匹配”标识依据。

## 输出设计

### 快速搜索输出

1. 一句话说明查询条件和结果总数。
2. 使用 Markdown 表格展示项目。
3. 项目名称必须使用 `[项目名称](真实外部链接)` 格式。
4. 基础字段包括项目名称、采购人、地区、预算、截止时间和匹配标记。

### 重点筛选输出

按“优先跟进、重点关注、储备关注”分组，每个重点项目提供匹配理由、主要风险和建议动作。只深入说明 3 至 5 个项目，其余项目保持简洁。

### 单项目分析输出

围绕项目概况、参与资格、技术需求、时间节点、风险和下一步动作组织，不重复输出无关的搜索结果。

## 不限条数与折叠规则

短系统提示词不设置固定的返回条数上限。接口返回且通过基础筛选的有效项目应全部保留。

- 结果较少时直接显示完整表格。
- 结果较多时，首屏展示查询概览和高匹配项目。
- 其余结果按匹配级别、地区或时间分组，使用 `<details><summary>` 包裹 Markdown 表格。
- 折叠只改变页面展示，不删除数据，也不移除项目链接。
- 若结果超过单次模型响应的技术容量，必须显示总数、当前已返回数量和剩余数量，并按后续批次继续，禁止静默截断。

K-ACP 当前 Markdown 渲染器和全局样式已支持 `details` 与 `summary` 折叠结构，因此第一版只需在短系统提示词中规定折叠原则，并由技能提供具体表格格式，无需修改前端组件。

## 错误与数据边界

- 未获取的字段显示“未获取”，不得编造。
- 无真实 URL 时项目名称使用普通文本，不生成假链接。
- 无法确认截止状态时标记“截止时间待核实”，不直接归为有效或已截止。
- 接口部分失败时返回已获得的数据并说明影响范围。
- 搜索结果为零时说明已使用的条件，并给出一个简短的放宽条件建议。
- 结果总数以接口实际返回或声明的数量为准，不将抽样数量写成全量数量。

## 内容分配与长度预算

### 短系统提示词

只保留：

1. 角色与业务输出目标。
2. 快速搜索、重点筛选、单项目分析的路由条件。
3. 对应阶段需要加载的技能。
4. 真实性、隐藏工具过程、连续追问和折叠规则。

目标长度约 600 至 1000 个中文字，不写 API 地址、参数表、企业画像字段明细、风险清单或大段示例。

### `tender-search`

继续负责招标 API、查询参数、详情接口、日期工具和项目外链。第一版不重构该共享技能，避免影响使用它的其他智能体。

### `tender-opportunity-analysis`

入口 `SKILL.md` 只写触发条件和引用路由，目标长度不超过约 2000 个中文字。筛选和单项目分析细则分别进入两个 reference 文件，仅在对应阶段读取。

## 验收标准

### 快速搜索

输入“查广东最近一个月服务器采购项目”时：

- 返回符合条件的项目列表，而不是深度研究报告。
- 项目名称能够点击并跳转到真实外部公告。
- 不限制有效项目总条数；项目过多时正确折叠。
- 只加载查询技能，不加载深度分析规则。

### 重点筛选

输入“哪些项目值得我们优先跟进”时：

- 沿用前一轮查询结果。
- 有企业画像时使用定制匹配，没有时使用通用匹配。
- 重点分析不超过 5 个项目，其余项目仅分组展示。
- 按需加载商机筛选参考文件。

### 单项目分析

输入“深入分析第 2 个项目”时：

- 正确定位前一轮的第 2 个项目。
- 查询详情后分析资格、技术、时间、风险和行动建议。
- 不编造缺失字段。
- 按需加载单项目分析参考文件。

### 异常与超长结果

- 接口失败时明确报告影响，不生成虚假数据。
- 折叠内容仍保留项目链接。
- 超过单次响应容量时明确显示返回进度，不静默丢弃结果。

## 实施范围

设计批准后，实施计划应只包含：

1. 编写精简的“商业标书智能体”系统提示词模板。
2. 新增 `tender-opportunity-analysis` 技能及两个按需 reference 文件。
3. 将新模板和新技能绑定到现有商业标书智能体。
4. 保留现有 `tender-search`、当前日期和公共 `http_request` 工具配置，不修改共享 `tender-search` 内容。
5. 使用上述三类对话和异常场景验证技能按阶段加载、外链和折叠效果。
