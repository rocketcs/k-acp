# 大屏视觉总监 Skill 与创作方案卡片设计

## 状态

已确认，待实现。

## 目标

让 `default-large-screen-image` 在用户上传参考图并点击“识图”后，产出稳定、可编辑、可直接交给生图 Tool 的大屏创作方案。用户看到的是类似 ChatGPT 生图工作流的创作方案卡片，而不是原始 JSON、工具协议或冗长提示词。

## 约束与边界

- 仅绑定 `default-large-screen-image`；不修改通用 Chat、DIY Chat、后端源码或数据库表结构。
- 仅修改/新增大屏专属前端模块，并新增平台内 Skill 包及其 Agent 绑定。
- 视觉识别模型为已验证支持 `image_url` 的 `gpt-5.4-mini-vision`。
- 生图仍委托给现有或后续配置的 `gpt-image-2` Tool；本设计不实现该 Tool 的服务端逻辑。
- 图库、跨会话资产管理继续留在 Phase 2。

## 方案选择

采用“专属 Skill 输出结构化创作方案 + 专属页面渲染卡片”。

不采用仅输出 Markdown 的方案：它无法提供可靠回填和可编辑结构。

不采用新增后端 JSON 接口：Skill 的稳定输出契约与隔离页面解析已能满足需求，且不违反不改后端源码的约束。

## Skill 定义

| 字段 | 值 |
| --- | --- |
| 平台稳定名 / Skill Key | `large-screen-image-visual-director` |
| 中文标题 | `大屏视觉总监` |
| 类别 | `大屏生图` |
| 绑定 Agent | `default-large-screen-image` |
| 触发条件 | 用户消息包含 `large-screen-image action=analyze` 且带有图片附件 |
| 职责 | 参考图解读、视觉抽象、可执行生图方案编排 |
| 非职责 | 直接生成图片、调用 Tool、编造不可见数据或品牌事实 |

### 视觉总监工作准则

1. 先区分“图片中可观察到的事实”与“为完整大屏提出的设计建议”。
2. 把风格、配色、层级、构图、图表、数据密度和场景转换为可执行的中文生图语言。
3. 保留用户明确指定的比例；没有指定时，推荐最适合该图的比例，并说明理由。
4. 不虚构品牌、业务数字、人物身份、数据指标或图片中不存在的交互能力。
5. 输出一份完整、可直接用于生图的正向提示词及紧凑的负面提示词。
6. 若参考图不清晰、内容不足或不是大屏，明确降低置信度并提供合理的补全建议。

## 输出契约

Skill 在最终回复中只输出一个带语言标识的代码块，页面以此作为解析协议：

````markdown
```large-screen-image-plan
{
  "version": "1",
  "title": "城市运行态势感知大屏",
  "confidence": "HIGH",
  "observedVisualFacts": [
    "深蓝低饱和背景与青色发光边框",
    "中心主视觉突出，左右分栏承载辅助信息"
  ],
  "designSuggestions": [
    "将中心区组织为核心 KPI 与区域地图",
    "右侧使用趋势、排行和告警状态形成纵向信息流"
  ],
  "creativeBrief": {
    "ratio": "16:9",
    "styleTags": ["科技感", "深蓝", "数据驾驶舱", "轻量发光"],
    "palette": ["#071B3A", "#00D9FF", "#2B75FF", "#FFB648"],
    "layout": [
      "顶部：标题、时间与全局状态",
      "左侧：地图与区域指标",
      "中心：核心 KPI、主图与事件焦点",
      "右侧：趋势、排行、告警与环比"
    ],
    "chartSuggestions": ["区域热力地图", "核心指标卡", "趋势折线图", "排行条形图"],
    "prompt": "16:9 城市运行态势感知数据大屏，深蓝色背景，青蓝色发光边框……",
    "negativePrompt": "低清晰度、杂乱文字、过度 3D、无意义装饰、错误图表、密集水印",
    "iterationHints": ["需要更商务时降低霓虹发光强度", "需要更多数据密度时增加右侧列表区"]
  }
}
```
````

### 契约规则

- `version` 固定为字符串 `"1"`。
- `confidence` 仅允许 `HIGH`、`MEDIUM`、`LOW`。
- `ratio` 仅允许 `16:9`、`21:9`、`9:16`。
- `observedVisualFacts` 只包含图中真实可见内容；`designSuggestions` 才允许补全建议。
- `prompt` 是用户可编辑、可直接送入生图 Tool 的完整中文正向提示词。
- `negativePrompt` 不超过 160 个中文字符。
- 不能在代码块外输出解释、寒暄、Markdown 标题或 Tool 调用文本。
- 当前 `action=analyze` 绝不调用生成或编辑 Tool/MCP；它只输出创作方案。

## 专属页面交互

### 识图成功

1. 页面收到助手消息后解析 `large-screen-image-plan` 代码块。
2. 解析成功时，将 `creativeBrief.prompt` 回填到专属页面的生图输入框，但不自动生成。
3. 消息区将原始协议隐藏为“已生成创作方案”，展示独立的创作方案卡片。
4. 创作方案卡片显示标题、置信度、比例、风格标签、布局、配色、图表建议与可编辑的正向/负面提示词。
5. 用户点击“生成大屏图”后，使用当前编辑后的提示词、比例和参考图发起生成；用户的编辑永远优先于 Skill 初始值。

### 卡片操作

| 操作 | 行为 |
| --- | --- |
| 重新识图 | 对当前参考图重新发起 `analyze` |
| 复制提示词 | 复制正向提示词 |
| 还原识图方案 | 恢复最近一次 Skill 的 `prompt` 与 `negativePrompt` |
| 生成大屏图 | 发送当前编辑后的生成请求 |
| 作为参考图 | 复用当前会话结果图，沿用现有专属页面能力 |

### 失败与降级

- Skill 输出不符合契约：保留原助手文本并显示“未能解析为创作方案，可重新识图”；不清空用户已编辑的输入。
- 视觉模型请求失败：显示可重试错误，不伪造方案。
- 识图时未附带图片：保持现有上传提示。
- Tool 尚未配置：创作方案仍可验收；“生成大屏图”应明确提示生图能力尚未配置，而不是假装生成成功。

## 数据与隔离

- Skill 内容存储为平台 `skill_package` 的 `SKILL.md` 文件，并使用 `agent_skill_packages` 仅关联目标 Agent。
- 当前平台没有独立 Skill Key 字段；`skill_package.name`、`SKILL.md` 的 frontmatter `name`、运行时 Skill 名和技能目录必须同为 `large-screen-image-visual-director`，后续不得仅修改其中之一。
- 不新增表、不修改已有 Skill、不更改通用 Agent 的系统提示词。
- 原始结构化回复已随现有会话消息保存；页面刷新后可重新解析，故不需要新增持久化字段。
- 新增解析器、类型与样式仅位于 `ui/src/features/large-screen-image/`。

## 验收标准

1. 新增的 `large-screen-image-visual-director` Skill 包仅存在一份、仅绑定 `default-large-screen-image` 一次；目标 Agent 已有的其他绑定保持不变。
2. 上传真实参考图并点击“识图”后，模型返回 `large-screen-image-plan/v1` 协议。
3. 专属页面显示创作方案卡片，不显示协议 JSON 或内部控制文本。
4. 正向提示词自动回填，用户修改后点击生成时使用修改后的内容。
5. 无法解析的模型回复不会破坏既有会话、上传或手动输入。
6. 删除大屏专属前端模块和解除该 Skill 绑定后，通用 Chat 与原 DIY Chat 保持正常。

## 验证方式

- 先为解析器编写失败用例：无代码块、非法 JSON、缺失必填字段、非法比例。
- 再实现解析器并验证有效方案、提示词回填与会话重载恢复。
- 验证 Skill 绑定只命中目标 Agent。
- 使用已验证的视觉模型和真实图片完成一次识图人工验收。
