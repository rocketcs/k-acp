# 商业标书追问策展 Skill 设计

## 背景与目标

商业标书智能体目前会在回复结束后注入固定的追问菜单。菜单没有引用当前项目、采购方、查询范围或分析结果，且四个选项主要是重复的检索方式，无法帮助销售或投标人员推进业务决策。

新增 `commercial-tender-followup-curator` Skill。它在主智能体完成当前问题后，基于已确认的业务事实、企业画像、招投标作战方法论和已启用能力，自主选择值得推进的问题，并直接输出后续追问卡片。

目标：

- 每张追问卡都指向明确的业务决策和预期产出。
- Skill 可主动提出用户尚未想到、但与当前商机有关的高价值方向。
- 卡片只推荐当前真实可执行的只读能力，不承诺尚未具备的自动化。
- 卡片来源唯一为 Skill 的结构化输出；前端不再维护固定菜单或翻译枚举值。
- 保留连续会话的条件、项目顺序和已完成动作，避免重复推荐。

非目标：

- 不自动创建监控、推送、收藏、任务、联系人消息或任何外部写入。
- 不实现 Excel/PDF 导出、CRM 写入或外联沟通。
- 不让 Skill 为生成卡片而自行编造项目事实、采购方关系或资格结论。
- 不取代搜索、商机筛选和单项目分析能力。

## 方案选择

采用“结构化事实包 + 专职策展 Skill”方案。

不采用仅依赖主智能体提示词的方案：它无法稳定保留具体实体，且在回复截断或 Skill 未加载时易退化为通用菜单。

不采用首版即重构全部入口为独立后处理工作流的方案：该方案最强制但改造范围大，超出首版所需。首版以统一事实包和明确路由约定连接现有搜索、筛选、项目分析入口；后续仅在稳定性不足时再升级为全入口强制工作流。

## 协作架构

```text
用户请求
  -> 主智能体/既有工作流：完成本轮搜索、筛选或项目分析
  -> 结果整理器：生成面向回答的文本和结构化 FollowupContext
  -> commercial-tender-followup-curator：提出、筛选并排序下一步动作
  -> 卡片校验器：验证事实引用、能力白名单、差异性和 UIP Schema
  -> 前端 UIP 渲染器：原样渲染唯一一张合法 Skill 卡片
  -> 用户点击：提交选项中的完整自然语言请求
  -> 主智能体：按常规意图路由执行下一轮
```

### 职责

| 组件 | 负责 | 不负责 |
|---|---|---|
| 主智能体/工作流 | 回答当前问题、查询数据、保存连续状态 | 维护固定后续菜单 |
| 结果整理器 | 将可信结果转换为事实包 | 判断业务下一步 |
| 策展 Skill | 发现信息缺口、生成并排序业务动作、输出卡片 | 伪造事实、执行写操作 |
| 校验器 | 拒绝不合法/不可执行/重复的卡片 | 改写 Skill 的业务意图 |
| 前端 | 渲染、点击提交、展示提交状态 | 推测卡片文案或把枚举值翻译为问题 |

## 事实包契约

每条有实质业务结果的回复都应产生 `FollowupContext`。其中只包含事实、稳定标识和当前可用能力；不包含模型内部推理、认证信息或公告全文。

```json
{
  "version": "1.0",
  "stage": "search_results",
  "originalIntent": "查广东近一个月反诈平台项目",
  "queryPlan": {
    "regions": ["广东"],
    "timeRange": {
      "start": "2026-06-26",
      "end": "2026-07-26"
    },
    "topic": "反诈平台",
    "bidStages": [4]
  },
  "resultState": {
    "totalKnown": 12,
    "displayed": 6,
    "remaining": 6,
    "isComplete": true,
    "selectedProjectIds": [],
    "completedActionKeys": []
  },
  "projects": [
    {
      "id": "bid-001",
      "title": "阳江市公安局涉诈预警处置平台",
      "buyer": "阳江市公安局",
      "region": "广东省阳江市",
      "stage": "招标中",
      "budget": null,
      "deadline": "2026-07-30",
      "matchReasons": ["反诈", "平台"],
      "factRefs": ["result:bid-001"]
    }
  ],

  },

```

`completedActionKeys` 在用户点击卡片后由下一轮结果写入，用于压制已完成或刚被拒绝的建议。没有足够事实的字段使用 `null` 或空数组，不能由策展 Skill 推断补齐。

## 策展 Skill

### 触发

仅在主流程已有面向用户的有效业务结果时触发：搜索结果、商机筛选、单项目分析、客户/竞争分析。纯闲聊、工具错误、权限不足和无业务输出时不触发。

零结果或低质量结果可触发，但只生成一个最小范围调整建议，且不得自动改变用户的地区、时间、主题或阶段。

### 自主策展方法

Skill 从四类候选动作中生成候选，再取最高价值且彼此不同的三至四项：

1. **决策推进**：资格、技术、评分、截止时间或项目可行性核验。
2. **客户与竞争洞察**：采购历史、历史供应商、同类项目中标格局。
3. **商机扩展**：相邻区域、相近主题、相同采购方或尚未查看的结果。
4. **画像匹配**：存在已确认企业画像时，按能力、案例和区域偏好重筛；画像缺失时不得假称“根据我方能力”。

每个候选按以下规则排序：预期业务价值、时间紧迫度、当前信息缺口、可执行性和与其他卡片的差异性。排序理由仅用于内部校验，不对用户展示为模型推理。

### 约束

- 最多四项；信息不足时少于四项或不出卡。
- 每项必须引用 `factRefs` 中的至少一个事实，或明确引用当前 `queryPlan` 的探索范围。
- 每项必须映射到 `availableActions` 中的一项。
- 同一轮不出现两个等价的搜索放宽建议，或两个针对同一事实、产出相同的分析建议。
- 不得推荐监控、导出、CRM、外联或其他不在白名单中的能力。
- 不得把未知截止日期描述为紧急，或把未验证预算、资质、联系人写成事实。
- 选项值是完整的自然语言用户请求，点击后可直接提交；不得使用前端专用枚举值。

## 输出与渲染契约

Skill 只返回一张合法的 UIP choice 卡片。`value` 为完整请求，`label` 为简短动作名，`description` 说明用户会得到的结果。卡片可允许用户输入自定义追问。

```json
{
  "role": "assistant",
  "content": "",
  "version": "2.0",
  "interaction": {
    "id": "tender-followups-dynamic",
    "type": "choice",
    "question": "基于这批结果，下一步先解决哪个决策？",
    "multiple": false,
    "allowCustom": true,
    "autoSubmit": true,
    "options": [
      {
        "value": "深入核验“阳江市公安局涉诈预警处置平台”的资格、技术参数和评分办法，判断我们是否值得投",
        "label": "判断是否值得投",
        "description": "补齐资格、技术和时间风险"
      },
      {
        "value": "查询近一年广东公安反诈项目的中标供应商，分析主要竞争对手与进入机会",
        "label": "摸清竞争格局",
        "description": "了解谁在做、怎样中标"
      },
      {
        "value": "扩大到佛山和江门，筛选仍可报名的反诈平台类项目",
        "label": "扩展更多可投机会",
        "description": "在相邻市场寻找同类窗口"
      }
    ]
  }
}
```

前端继续使用现有 UIP Schema 校验和自动提交机制，但不再注入 `tender-followups` 固定菜单。若 Skill 没有产生合法卡片，界面不显示追问卡片；这比显示虚假的动态建议更可靠。

## 连续会话规则

- 用户选择卡片后，选项 `value` 原样作为下一轮用户问题提交。
- 主智能体按当前意图正常路由，不把卡片选择视为特殊枚举。
- 下一轮事实包继承上一轮的 `QueryPlan`、稳定项目顺序、分页状态和 `completedActionKeys`。
- 如果用户切换话题或上一轮状态缺失，Skill 只根据可确认的当前事实生成卡片，不假装掌握旧会话上下文。

## 错误与降级

- 事实包缺失、Schema 无效或卡片无法通过能力校验：不渲染卡片，记录可诊断原因。
- Skill 输出包含未启用动作：剔除对应选项；没有剩余选项则不渲染。
- 选项没有事实引用、引用不存在实体或重复动作：剔除该选项。
- 只有分页状态且没有项目事实：最多可保留“继续查看剩余结果”一项。
- 查询失败：主回答说明失败范围；策展 Skill 不生成假设性的后续分析卡。

## 验收标准

1. 对具体项目结果，至少一张卡引用该项目并推荐详情或可行性分析。
2. 对包含多个项目的结果，卡片覆盖至少两个不同决策维度，不重复同类筛选。
3. 对结果不足或零结果，只提供有边界的最小放宽/调整建议。
4. 画像缺失时不出现“根据我方能力”；画像存在时可出现画像匹配动作。
5. 每个选项都能映射到能力白名单，且 `value` 可作为完整下一轮请求执行。
6. 不出现监控、导出、外联、CRM 写入或其他未实现能力。
7. Skill 缺失或输出无效时，不展示静态 `tender-followups` 菜单。
8. 已点击的动作不会在紧随其后的等价场景再次被推荐。

## 实施边界

实现将涉及商业标书智能体配置/Skill 绑定、现有业务结果到事实包的传递、追问卡片输出与前端静态兜底的移除或限制，以及对应单元/集成测试。不会修改标讯外部 API、共享 `tender-search` 数据契约、数据库结构或任何远程环境。
