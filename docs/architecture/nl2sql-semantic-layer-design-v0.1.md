## 1. 背景与目标

### 1.1 背景

客户场景为**对话式数据查询（问数）**：业务人员用自然语言提问，系统返回准确的数据结果，
并附带可追溯的依据（口径说明、来源表字段、推理路径）。

本项目已向客户承诺基于 **Neo4j 知识图谱**构建智能问数能力。当前已具备的前期资产
（详见 [附录 A](#附录-a已有资产盘点与复用)）：

- DM8 模拟业务库（电力物资域，v0.2，约 10 张表，2 万条库存记录）
- Neo4j 中文知识图谱（v0.2，仓库/库存/物资/供应商/项目/区域，6 类中文关系）
- 中文本体映射（`ontology-mapping-cn-v0.1.json`）与 SHACL 约束（`ontology-shapes-cn-v0.1.ttl`）
- 电力调度驾驶舱渲染页（`dm8-graph-demo-cn.html`，图谱/表格双视图）
- 6 组标准问数样例（`query-*.json`）

### 1.2 目标

1. **准确**：在已注册语义层范围内，单表与多表问数准确率 ≥ 85%（以评测集为准）
2. **可信**：每个答案附带证据链——口径说明、来源表字段、实体识别依据；未建模问题**拒答并引导登记**，不编造
3. **人机协作**：语义层（五类定义）由 Agent 起草、业务人员确认后发布生效，全程不依赖全自动
4. **图谱兑现**：Neo4j 承载语义图谱与实体识别，可视化可演示，是问数引擎的真实组件而非摆设
5. **可演进**：架构预留阶段二能力（制度文档规则抽取、审核判断、血缘分析）的扩展点

### 1.3 非目标（MVP 明确不做）

- ❌ 跨库联邦查询（不做 MySQL/DM/PG 跨源联合）
- ❌ 制度文档规则抽取与审核判断（阶段二）
- ❌ 大规模数仓（数百张表）的 schema 检索裁剪（当前 10 张表全量常驻上下文）
- ❌ 数据写入类操作（问数只读）

```

└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│                Agent 编排层（Apboa Next / AgentScope）         │
│  ┌──────────────┐   ┌──────────────────────────────────────┐ │
│  │ 语义层构建 Agent│  │         问数 Agent（规划器）           │ │
│  │ 起草五类定义    │  │  ①术语/指标/实体识别 ②生成执行计划      │ │

└─────────┼───────────────────────────┼────────────────────────┘
          │                           │
┌─────────▼─────────┐    ┌────────────▼─────────────────────────┐
│  语义层建设工作台    │    │      确定性执行器层（非 LLM）           │
│  草稿→确认→发布     │    │  SQL执行器 │ 图查询执行器 │ 指标执行器   │

│  ┌──────────────────┐  ┌──────────────┐  ┌───────────────┐   │

│  │ 五类定义DSL/版本   │→ │ 语义/实体值/   │  │ MOCK_APP      │   │
│  │ 状态机/评测集/审计  │  │ 证据链/轨迹   │  │ （只读账号）    │   │

└──────────────────────────────────────────────────────────────┘
```

### 2.2 核心设计原则

| # | 原则 | 说明 |
|---|------|------|
| 1 | **LLM 只在两端** | LLM 出现在链路两端（理解意图、组织语言），中间所有"查"与"算"由确定性执行器完成。保证答案可复现、可追责 |
| 2 | **单真源、多处投影** | 五类定义的权威来源是元模型库（关系库）；Neo4j 是发布后的投影，专职图查询与可视化。改定义永远改真源 |
| 3 | **指标优先** | 问题命中计算定义（指标）时展开指标 DSL 而非生成裸 SQL，保证全系统口径唯一；未命中指标才走裸 SQL 并在答案中标注"非标准口径" |
| 4 | **人在回路** | 所有定义走"草稿 → 已确认 → 已发布"状态机；问答引擎只消费已发布版本 |
| 5 | **拒答优于编造** | 语义层未覆盖的问题拒答 + 引导登记，拒答率纳入监控 |

### 2.3 技术栈

| 组件 | 选型 | 说明 |
|------|------|------|
| 平台底座 | Apboa Next（Java 21 / Spring Boot 3.4 / AgentScope） | Agent 编排、模型接入、会话管理复用平台能力 |
| 元模型库 | 平台现有元数据库（MySQL/PG，JSON 列存 DSL） | 五类定义、版本、状态机、评测集、审计 |
| 图数据库 | Neo4j 5.x（已有容器 `k-acp-neo4j-mock`，bolt://127.0.0.1:7689） | 语义图谱、实体值图谱、证据链、问答轨迹 |
| 业务库 | DM8（已有容器 `dm8-mock`，MOCK_APP 模式） | 只读账号接入；SQL 方言按 DM8 MySQL 兼容模式 |
| SQL 解析 | JSqlParser | 只读判定、权限谓词注入、LIMIT 注入 |
| 前端 | Vue 3.5 | 工作台 + 问答界面；图谱可视化复用/扩展 ECharts 驾驶舱 |
| LLM | 平台多模型接入（私有化：DeepSeek/Qwen 系） | 规划、生成、合成；不用于最终判定 |

## 3. 核心模型：五类定义（语义层）

五类定义是整个系统的核心资产，构成层级依赖链：
**数据定义 → 图定义 → 计算定义 → 规则定义**，知识定义贯穿实例层。

### 3.1 数据定义（字段语义注册）

| 项 | 内容 |
|---|---|
| 实质 | 表/字段级语义注册：业务含义、同义词、数据类型、枚举值、清洗口径 |
| 存储 | 元模型库，`semantic_table` / `semantic_field` |
| 问数作用 | 字段定位、同义词映射、类型校验 |

DSL 示例：

```json
{
  "id": "fld-stock-amount",
  "table": "stock_record",
  "column": "actual_total_price",
  "businessName": "库存金额",
  "synonyms": ["金额", "库存价值", "总金额", "价值"],
  "dataType": "decimal(18,2)",
  "unit": "元",
  "description": "库存记录的实际总金额，= 数量 × 单价，含 13% 增值税口径",
  "sampleValues": [4400000.00, 1636.00]
}
```

### 3.2 图定义（本体 / Join 路径）

| 项 | 内容 |
|---|---|
| 实质 | 实体类型、关系类型（= 表间 Join 路径的语义化）、约束 |
| 存储 | 元模型库（真源）+ Neo4j 语义图谱（投影） |
| 初始来源 | 由已有 `ontology-mapping-cn-v0.1.json` 转换为正式 DSL |

DSL 示例（关系 = Join 路径）：

```json
{
  "id": "rel-stock-supplier",
  "name": "由供应商提供",
  "from": {"entity": "库存记录", "table": "stock_record"},
  "to":   {"entity": "供应商",   "table": "vendor"},
  "joinCondition": "stock_record.vendor_id = vendor.vendor_id",
  "cardinality": "N:1",
  "description": "每条库存记录由唯一供应商提供"
}
```

### 3.3 计算定义（指标层，问数的灵魂）

| 项 | 内容 |
|---|---|
| 实质 | 结构化计算 DSL：属性级运算、跨实体聚合、关系推导 |
| 存储 | 元模型库（真源）+ Neo4j `DEPENDS_ON` 血缘（投影） |
| 关键机制 | 一份 DSL 编译为 SQL（DM8 方言）与 Cypher 两种执行形态，杜绝口径漂移 |

三级计算：

| 级别 | 电力物资域示例 |
|------|---------------|
| 属性级 | `库存记录.金额 = 数量 × 单价`（v0.2 数据已严格保证）；`库龄档位 = f(入库日期, 基准日)` |
| 聚合级 | `仓库.库存总金额 = SUM(其库存记录.金额)`；`物资.全省库存量 = SUM(各仓库库存记录.数量)` |
| 关系推导 | `(供应商)-[竞争]->(供应商)`：同物资价格差 >10% 的两个供应商 |

DSL 示例（含显式口径假设——人机协作的核心）：

```json
{
  "id": "metric-aged-scrap-amount",
  "name": "超龄报废库存金额",
  "target": "agg:sum",
  "expression": "SUM(库存记录.金额) WHERE 库龄档位 IN ('5-10年','10年以上') AND 用途 = '报废'",
  "assumptions": [
    "库龄档位由入库日期按基准日 2026-08-28 推导",
    "'报废' 取用途编码 SCRAP，不含闲置(IDLE)"
  ],
  "dependsOn": ["fld-stock-amount", "calc-stock-age", "fld-stock-usage"],
  "materialize": "virtual",
  "resultType": "decimal(18,2)"
}
```

**口径假设机制**：Agent 起草指标时必须把所有隐含假设显式列入 `assumptions`，
业务人员在确认界面逐项勾选/修正后才能发布。

校验器三件套（Agent 起草后的机器关卡）：

1. **DAG 校验**：指标可互相引用，拓扑排序检测循环依赖
2. **类型检查**：依赖字段类型不兼容直接拒绝
3. **血缘记录**：依赖链写入 Neo4j，支持影响分析（"改了用途字段口径，哪些指标受影响"）

### 3.4 规则定义（MVP 降级为查询约束）

问数场景下规则定义的实际作用是**数据权限与默认过滤**：

```json
{
  "id": "rule-perm-bureau",
  "type": "row_filter",
  "target": "仓库",
  "expression": "仓库.地市局编码 IN (:user_bureaus)",
  "description": "地市局用户仅可查询本局仓库",
  "appliesTo": ["仓库", "库存记录", "库存汇总"]
}
```

完整的 IF-THEN 业务规则引擎（制度文档抽取、审批判断）推迟到阶段二，
但规则定义的 DSL 结构与状态机现在就定型，避免阶段二返工。

### 3.5 知识定义（实例三元组）

| 项 | 内容 |
|---|---|
| 实质 | 实例数据：从业务库同步的实体与关系（已有 v0.2 图谱，2 万+ 关系） |
| 存储 | Neo4j 实例层（唯一存放处）+ 元模型库登记同步水位 |
| 同步 | 全量重建（当前规模 < 1 分钟）或按变更增量；记录同步水位与数据版本号 |

### 3.6 定义状态机（所有五类统一）

```
草稿(draft) → 已确认(confirmed) → 已发布(published) → 已归档(archived)
     ↑                                │
     └──────── 修订(新版本草稿) ◀──────┘
```

- 问答引擎**只消费 published** 版本
- 每次问答记录所引用定义的精确版本号，历史答案可复现
- 归档版本保留，供历史答案审计

## 4. Neo4j 语义图谱设计

### 4.1 图模型（在已有 v0.2 图谱上扩展）

已有 v0.2 图谱覆盖**实例层**（仓库/库存/物资/供应商/项目/区域）。本次扩展**语义层**节点：

```
语义层节点                        实例层节点（已有 v0.2）
┌──────────┐                    ┌──────────┐
│ :Table    │──:HAS_FIELD──▶    │ :Field    │        :仓库  :库存记录  :物资
└──────────┘                    └──────────┘        :供应商 :项目 :区域
┌──────────┐  :MAPPED_TO
│ :Term     │──────────▶  :Field / :Metric / :EntityValue
│ (术语/黑话)│
└──────────┘
┌──────────┐  :DEPENDS_ON
│ :Metric   │──────────▶  :Field / :Metric（DAG 血缘）
│ (指标)    │──:ASSUMES─▶ :Assumption（口径假设）
└──────────┘
┌────────────┐ :VALUE_OF
│ :EntityValue│─────────▶ :Field     （员工/仓库/物资名等高频值）
│ "1号仓库"   │
└────────────┘
┌────────────┐ :USED  :RESOLVED_AS
│ :QueryTrace │─────────▶ 本次问答命中的 Term/Metric/Field/EntityValue
│ (问答轨迹)  │
└────────────┘
```

实体值节点与实例节点的关系：`:EntityValue` 挂 `:Field`（注册词汇），
命中后通过已有映射规则（`ontology-mapping` 的 URN 体系）跳转到实例节点。

### 4.2 图谱的四个角色（客户承诺的兑现点）

| # | 角色 | 真实功能 | 演示点 |
|---|------|---------|--------|
| 1 | 语义图谱 | 术语→字段→指标的多跳定位；"钱相关的字段"语义检索 | 语义层管理界面图谱浏览 |
| 2 | 实体值图谱 | 实体链接："1号仓库"→`:EntityValue`→仓库实例→所在区域→权限范围 | 问答时展示识别过程 |
| 3 | 证据链图谱 | 每个答案的推导路径存图：命中指标→依赖字段→口径→SQL | 答案下方一键展开推导图 |
| 4 | 问答轨迹图谱 | 高频未命中问题 → Agent 自动建议新指标/新术语 | "知识缺口发现"演示 |

### 4.3 同步机制

- 发布动作触发同步器：元模型库 → Neo4j（语义层节点全量小、可全量重建）
- 事后的图校验任务：比对真源与投影的定义集合，不一致告警
- URN 体系沿用 `urn:kacp:mock:` 命名空间与现有约定（URN 不进入展示层）

## 5. 人机协作流水线（HITL）

### 5.1 流水线节点

| # | 节点 | Agent 干什么 | 人干什么 | 界面 |
|---|------|-------------|---------|------|
| 1 | 摄取解析 | 扫描 schema + 数据样本（全自动） | 处理异常 | 异常通知 |
| 2 | 数据定义 | 起草字段含义、同义词、枚举 | 逐项确认 | 工作台表格 |
| 3 | 图定义 | 起草实体/关系/Join 路径（基于已有 mapping 转换） | 确认业务概念正确完整 | 图形化确认 |
| 4 | 计算定义 | 起草指标表达式 + **显式口径假设** | 逐项确认假设、修正表达式 | 指标确认页 |
| 5 | 知识定义 | 同步实例入图 | 抽检样本 | 抽检队列 |
| 6 | 发布 | 生成版本差异报告 + 触发图同步 | 决定发布时机 | 版本对比页 |

### 5.2 关键设计

1. **草案带出处**：Agent 每条草案标注来源（schema 推断 / 数据样本 / 已有 mapping 文件），降低确认成本
2. **对话 + 工作台双通道**：单条修正可对话式完成（"把超龄的门槛改成 3 年"），批量确认走结构化工作台
3. **10 张表的规模下，语义层首次建设约 1~2 周**（人工 + Agent 辅助），之后按需增量维护

## 6. 问答执行引擎

### 6.1 执行链路

```
"库龄5年以上的报废物资还有多少金额？"
   │
   ▼
Agent 规划器（LLM）
  ① 实体/术语识别："报废"→枚举值(SCRAP)；"库龄"→计算定义 calc-stock-age
  ② 指标命中：无精确命中 → 退化为组合查询（SUM金额 + 过滤），标注非标准口径
  ③ 圈定表：库存记录（全 schema 语义描述常驻上下文，约 3~5K token）
   ▼
SQL 生成器（LLM，输入已被语义层裁剪与标注）
  输出候选 SQL
   ▼
校验器（确定性，JSqlParser）
  仅 SELECT/WITH √ 禁用函数黑名单 √ 强制 LIMIT √
  行级权限谓词注入 √ EXPLAIN 预检（防全表扫卡死）√
   ▼
SQL 执行器（DM8 只读账号）
   ▼
合成器（LLM）：结果表格 + 一句话结论 + 口径说明 + 证据链
  （合成器只允许引用执行器输出，不得引入外部事实）
```

### 6.2 问题路由

| 问题类型 | 示例（电力物资域） | 主执行器 |
|---------|-------------------|---------|
| 实体查询 | "1号仓库还有哪些物资" | SQL（经实体链接） |
| 聚合问数 | "全省变压器库存总金额" | 指标执行器（若已定义）→ SQL |
| 带过滤分析 | "库龄 5 年以上的报废物资有哪些" | SQL + 计算定义展开 |
| 排名类 | "库存金额 Top3 的物资" | SQL |
| 关系类 | "汉森 CNC 供过哪些物资、供给了哪些仓库" | 图查询执行器（Cypher）或 SQL |
| 术语解释 | "什么是闲置物资" | 语义图谱检索（Term 节点） |
| 未建模 | "明年采购预算多少" | **拒答** + 引导登记 |

### 6.3 实体链接（值索引）

- 高频实体值（仓库名、物资名、供应商名、项目名、区域名）预构建为 `:EntityValue` 节点
- 检索：Neo4j 全文索引 + 可选向量索引（规模小，全文优先）
- 未命中处理：模糊提示候选（"您是指『1号中心仓库』吗"），仍失败则拒答
- **这是问数准确率的隐形大头**：实体匹配靠检索，不靠 LLM 猜

### 6.4 答案标准结构

```json
{
  "question": "库龄5年以上的报废物资还有多少金额？",
  "conclusion": "全省超龄报废库存金额合计 5.03 亿元，共 1,996 笔",
  "table": [...],
  "evidence": [
    {"type": "entity",  "detail": "『报废』→ 用途编码 SCRAP（枚举表）"},
    {"type": "compute", "ref": "calc-stock-age v1", "detail": "库龄由入库日期推导，基准日 2026-08-28"},
    {"type": "scope",   "detail": "非标准口径：SUM 直接聚合，未经指标定义确认"},
    {"type": "data",    "ref": "stock_record", "source": "DM8.MOCK_APP"}
  ],
  "trace": {"planSteps": [...], "sql": "...", "definitionVersions": {...}}
}
```

## 7. 安全与权限

| 项 | 方案 |
|---|------|
| 业务库接入 | 独立只读账号，仅 SELECT 权限 |
| SQL 白名单 | 仅 SELECT/WITH；禁用 `SLEEP`、`LOAD_FILE` 等函数黑名单 |
| 结果限制 | 强制 LIMIT（默认 1000，可配置）；大结果集走聚合提示 |
| 行级权限 | 规则定义（row_filter）在 SQL 生成后强制注入 WHERE 谓词 |
| 审计 | 每次问答记录：问题、执行计划、SQL、结果摘要、引用定义版本、耗时、用户 |
| 凭证管理 | 数据库凭证不进入前端代码/日志（沿用交接文档约定） |

## 9. 评测体系（问数项目的生命线）

- **评测集**：30~50 个真实业务问题 + 标准答案 + 标注类型，YAML 管理
  - 种子来源：已有 `query-*.json` 六组样例直接转为评测用例
  - 覆盖：§6.2 各问题类型 + 边界 case（含 5~8 个应拒答问题）
- **指标**：执行准确率（结果比对）、证据链完整率、拒答正确率、P95 延迟
- **流程**：迭代 1 起积累，此后任何提示词/模型/语义层改动必须跑回归
- 这是区分"可交付产品"与"demo"的分水岭

## 10. 风险清单

| # | 风险 | 等级 | 对策 |
|---|------|------|------|
| 1 | 口径歧义导致"答非所想" | 高 | 指标显式假设机制（§3.3）；答案标注口径；反馈闭环 |
| 2 | DM8 SQL 方言与 JSqlParser 兼容缺口 | 中 | 迭代 0 做方言 spike 验证；兜底走 DM8 MySQL 兼容模式 |
| 3 | LLM 生成错误 SQL | 中 | 校验器 + EXPLAIN 预检 + 评测回归；错误 SQL 不出执行器 |
| 4 | 实体值匹配失败（别名/简称） | 中 | 值索引 + 候选确认交互；未命中引导登记 |
| 5 | 语义层腐化（有人建没人养） | 中 | 轨迹图谱自动发现知识缺口；月度语义层健康报告 |
| 6 | Neo4j 双写不一致 | 低 | 单真源原则 + 定期图校验任务；语义层节点可全量重建 |
| 7 | 合成器幻觉（引入执行结果之外的事实） | 中 | 合成器提示词强约束"只引用执行器输出"；评测集含证据链核查项 |
| 8 | 拒答率过高影响体验 | 中 | 拒答率监控；优先扩充高频未命中术语 |

## 11. 演示脚本要点（向客户）

1. **看见知识**：打开语义层图谱——表/字段/指标/术语在 Neo4j 中可视化为中文图谱
2. **问数**："全省变压器库存总金额" → 秒级返回表格 + 结论 + 口径说明
3. **看见思考**：展开答案证据链——实体识别、指标口径、SQL、来源表在图上亮起
4. **关系能力**："汉森 CNC 供过哪些物资、分布在哪些仓库" → 走图谱关系查询
5. **诚实拒答**："明年采购预算多少" → "该问题尚未建模，是否登记？" → 登记后 Agent 建议新指标
6. **口径演进**：把"超龄"门槛从 5 年改成 3 年 → 发布 → 重问，口径即时生效且历史答案可按旧版本复现
